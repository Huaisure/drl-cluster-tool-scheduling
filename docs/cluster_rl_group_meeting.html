01 · Problem framing

难点不是“走哪条路”，而是资源、时间与顺序同时耦合

01

工艺顺序

每片晶圆必须依次完成 Route；每一步可能对应多个候选腔室。

02

资源竞争

机械手、手臂、腔室容量与接口在同一时间只能服务有限任务。

03

异步时间

加工、移动、Pick、Place、Pump/Vent 均有持续时间，完成时刻不同。

04

全局目标

局部可行动作很多，目标却是降低整批晶圆的 makespan，并避免死锁。

建模目标：在任意决策时刻，从所有合法事件中选择下一步，使系统持续推进并尽量缩短总完工时间。

02 · Event-driven environment

先用离散事件刻画物理世界，再让 RL 做策略选择

STATE

状态是设备快照

晶圆位置与步骤、腔室占用、机械手持片与当前阶段、剩余加工/转换时间。

LEGALITY

Engine 生成合法动作

可达性、容量、持片、工艺完成和 LL 侧别等约束，不交给网络“猜”。

CLOCK

ADVANCE 推进时间

当动作已经排入设备，环境跳到下一个事件边界，避免逐秒空转。

Pick.start占用手臂与源接口
Pick.end释放源腔室容量
Place.start预占目标腔室容量
Place.end晶圆进入目标，释放手臂
职责分离：Engine 负责“物理上能不能做”，Policy 负责“合法动作里选哪个”。

03 · Markov decision process

用三个原子动作，覆盖机械手调度的决策闭环

Pick(w, r)选择晶圆与执行机械手；从模块取片。
Place(w, m)选择手中晶圆与目标模块；机械手由状态唯一确定。
Advance推进到下一事件边界，让加工或搬运动作完成。

终止条件

成功：所有晶圆完成 Route 并返回源端。
失败：未完成且合法动作集合为空，判定死锁。

OPTIMIZATION SIGNAL
环境奖励 = − Δt
成功回报 = − makespan

PPO 训练时再用参考 makespan 构造有界时间代价：成功额外 +1；死锁按未完成进度施加更强惩罚。这样既保留“越快越好”，又拉开成功与死锁。

05 · HGT + action-query decoder

先理解全局设备状态，再逐个判断合法动作

INPUT异构节点特征

各类型分别线性编码到统一维度。

ENCODERHGT 消息传递

按节点类型和关系类型聚合，形成上下文化实体表示。

QUERY只构造合法动作

Pick = wafer + robot；Place = wafer + module；Advance = global。

DECODERTransformer 解码

动作 query 对整张图 memory 做交叉注意力。

OUTPUT紧凑动作 logits

只在合法集合上采样或贪心选择，再映射回 Env 动作。

Actor：动作级输出每个合法动作一个 logit；不同实例允许不同动作数。
Critic：状态级输出从 global 节点预测 V(s)，为 GAE 与 PPO 更新提供基线。

06 · Training loop

PPO 学“相对更好”的调度，Validator 守住最终可信度

并行采样

多环境独立 rollout；策略仅从合法动作分布采样。

优势估计

按时间奖励计算 GAE；只对真正存在选择的状态归一化 Actor 优势。

PPO 更新

Clipped policy loss + clipped value loss + entropy，限制单次更新幅度。

贪心评估

固定验证集上比较 success 与 normalized cost；最佳模型独立保存。

训练数据固化 manifest / 在线生成 / 固定场景
参考尺度每个问题使用已验证 reference makespan，跨实例归一化
结果复核完整动作序列交给独立 ValidatorSuite
关键不是让神经网络替代约束求解，而是让它在被约束后的可行空间中学习调度偏好。

08 · Current boundary & next proof

体系已经成形，下一阶段要把“能跑”变成“可信且更优”

NOW · 已具备
  • 事件驱动的 Gym 环境与可变规模动作空间
  • Engine 提供合法动作掩码与死锁判定
  • 5 类节点的异构图状态协议
  • HGT + Transformer Actor-Critic 与 PPO 训练闭环
  • 固定数据集、参考 makespan、checkpoint 与 Validator 评估
NEXT · 需要证明
  • 扩大 train / validation / test 规模，报告均值与分位数
  • 与 FIFO、遗传算法和参考调度做统一基准对比
  • 分难度与拓扑评估 success、normalized cost、deadlock
  • 做动作掩码、图关系、HGT 与 decoder 的消融实验
  • 将清洗纳入策略动作或分层决策，并专项验证驻留约束
当前正确定位：完整的方法原型 + 初步闭环验证，而不是已经完成的大规模性能结论。
