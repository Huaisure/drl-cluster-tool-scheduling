2. 为什么需要这套数据生成框架

目标不是生成尽可能多的随机实例，而是构造一批接近实际设备分布、覆盖关键调度难点、又能被不同算法统一求解和比较的问题，最终为学习型调度提供可靠训练信号。

数据是否接近真实机台？ 如果拓扑、可达关系和腔室数量完全随机，生成的大量问题在真实设备上并不存在。
标签是否足够可靠和多样？ 单一算法会把自身偏好带入数据；只保留一个结果也无法判断解的质量与问题难度。
数据能否转化为学习信号？ 最终需要的不只是 makespan，还包括合法动作轨迹、参考尺度、难度信息和泛化测试问题。

基本思路：用有限、真实的硬件结构约束问题分布；在每种结构内部随机化 Recipe、加工时间和 workload；再通过不同类型算法产生互补的解与质量信息。

3. 为什么固定拓扑结构

实际产线中的 Cluster Tool 并不是任意图。Cell 数量、每个 Cell 的 PM 数量、Robot 配置和跨 Cell 的 BUFFER 连接通常来自有限的设备设计。因此，完全随机拓扑虽然增加了形式上的多样性，却会把训练分布推离真实机台。

固定的是硬件结构

  • Cell 数量与相邻关系；
  • 每个 Cell 的 PM、AL、BUFFER 数量；
  • Robot 的单双臂配置与可达范围；
  • 跨 Cell 搬运必须经过的物理连接。

随机的是生产任务

  • Recipe 数量、步骤数与经过的 Cell；
  • 每一步的候选 PM、重入与是否经过 AL；
  • 加工、搬运和对准时间；
  • 各 Recipe 的 wafer 数量与混合比例。
方案优点主要问题
完全随机拓扑形式多样，容易扩充数量容易生成现实中不存在或极少出现的设备结构，训练分布与实际应用脱节
只使用单一拓扑问题简单、便于调试模型容易记住固定结构，难以判断跨设备泛化能力
有限拓扑族 + 任务随机化保持物理真实性，同时覆盖不同负载、工艺和瓶颈需要后续用真实设备统计继续调整各类拓扑与任务的采样权重

这里固定拓扑不是为了降低问题难度，而是为了让数据多样性发生在真实会变化的部分：Recipe、加工时间、产品组合和投片规模。

1. 整体目的与总体框架

前期已经建立了事件驱动的调度环境和独立 Validator，统一了状态演化、合法动作、设备占用与时间约束。在这一基础上，当前工作的整体目的是构造接近真实机台分布的调度问题，用多种互补算法产生可信且多样的标签，再把这些标签转化为模仿学习样本、强化学习参考和统一评测基准。

4. 为什么选择这四类算法

四类算法不是简单重复求同一个答案，而是分别覆盖精确求解、结构化求解、全局启发式搜索和局部前瞻。它们共同提供“解的质量、求解速度、最优性信息和策略多样性”。

非周期 CP-SAT 完整有限批次

为什么选
它直接描述完整批次中的资源冲突、动作顺序与候选腔选择，是最清晰的精确优化基线。
预期效果
在小中规模问题上应提供质量较高的解，并可能给出全问题下界或最优性证明。
局限
随着 wafer 数和动作数增加，模型规模快速增长；大问题上可能主要提供 incumbent，而无法在预算内证明最优。

周期 CP-SAT 重复生产结构

为什么选
量产场景往往重复处理稳定的产品组合。周期模型直接优化稳态节拍，避免把大量相似 wafer 全部展开后再求解。
预期效果
在重复性强、批量较大的场景中，求解规模对 wafer 总数更不敏感，有机会更快获得高吞吐调度。
局限
启动、稳态和排空需要组合；子问题最优不代表整个有限批次全局最优，对非重复 workload 也不适用。

遗传算法 随机化全局搜索

为什么选
它不依赖精确模型的证明过程，容易在固定时间内探索不同调度顺序，并通过多次 seed 获得策略多样性。
预期效果
适合作为较大问题的可行解来源，也能补充 CP-SAT 未探索到的不同动作轨迹。
局限
解质量和稳定性依赖种群、代数与随机 seed；没有下界，无法证明离最优还有多远。

分支搜索 有限前瞻决策

为什么选
它在每个决策点向前枚举有限步，再执行第一步，行为直观，适合回答“多看几步是否比贪心更好”。
预期效果
可提供一个可解释、与在线决策更接近的基线；不同 horizon 能直接体现前瞻深度的收益与代价。
局限
搜索树随 horizon 增长很快，局部最优不保证全局质量；有限前瞻仍可能找不到安全延续。

组合这些算法的原因：CP-SAT 提供质量与证明信息，周期法利用生产结构，遗传算法补充全局随机探索，分支搜索提供可解释的在线决策基线。最终训练数据不必只来自某一个算法，而应从所有合法结果中选择或组合。

5. 这些算法目前效果如何

当前仓库已经完成四类求解路径的可行性和统一验证接入，但尚未在覆盖主要拓扑、Recipe 数和 wafer 规模的统一数据集上完成系统 benchmark。因此，现在可以说明算法机制和适用场景，不能提前宣称哪一种算法整体最好。

当前已经能够确认

  • 四类方法都按照同一物理语义产生完整调度；
  • 候选结果都经过同一个严格 Validator；
  • 非周期 CP-SAT 可以提供完整问题的下界与最优性状态；
  • 周期法可以构造可验证的启动、稳态与排空调度；
  • 遗传与分支搜索能够提供不同机制的启发式基线。

当前还不能下结论

  • 不同规模下哪种算法的有效解率最高；
  • 在相同时间预算下，谁的 makespan 更低；
  • 周期法从多大批量开始优于完整展开；
  • 遗传算法多 seed 的收益是否值得额外计算；
  • 分支搜索增加 horizon 后，质量提升是否抵得上节点增长。

需要验证的工作假设

  1. 小中规模问题中，非周期 CP-SAT 应是解质量和最优性证明的主要来源。
    验证方式：比较 best-makespan win rate、certified gap 和规定预算内的最优率。
  2. 在重复性强的大批量 workload 中，周期法应比完整展开更容易扩展。
    验证方式：随 wafer 数增加比较运行时间、首次可行解时间与最终 makespan。
  3. 遗传算法应能较稳定地产生可行解，但质量方差会随 seed 和问题结构变化。
    验证方式：报告多 seed 的中位数、分位数和相对 portfolio best 的 gap。
  4. 分支搜索的浅 horizon 适合作为快速基线，深 horizon 可能改善局部选择但计算量快速增加。
    验证方式：比较 horizon、展开节点数、运行时间和 makespan 的变化。
有效解率在预算内得到合法完整调度的比例
解质量相对 portfolio best 的 makespan gap
首次可行时间多久能产生第一条可用轨迹
最终运行时间达到最终 incumbent 或终止的耗时
证明能力最优率、下界和 certified gap
规模敏感性随 wafer、Route 和拓扑复杂度的退化

6. 生成的数据怎样用于下一步训练

每个实例最终提供两类信息：一类是问题本身，用于重建调度环境；另一类是经过验证的调度结果，用于提供动作示范、参考 makespan 和经验难度。它们可以分别进入模仿学习、强化学习和评测。

从调度结果提取监督信号

1
回放合法调度轨迹在每个决策时刻恢复设备状态与当时的合法动作集合。
2
构造 state–action 样本把 solver 选择的 Pick、Place 或 Advance 作为监督标签。
3
模仿学习预训练先让策略学会基本调度行为，减少 RL 初期的无效探索和死锁。

从结果质量提取强化学习信号

1
参考 makespan用当前最好合法解作为实例尺度，构造跨问题可比较的 normalized cost。
2
PPO 继续优化策略不必复制 solver，可以在合法动作空间内寻找比示范更好的动作组合。
3
独立验证策略输出完整 rollout 再经 Validator 检查，评价 success、makespan 与 deadlock。
数据内容在训练中的用途使用原则
问题结构构造环境状态、异构图和合法动作集合策略只看到调度状态，不需要知道标签来自哪个 solver
完整合法动作轨迹行为克隆、离线预训练、动作价值辅助任务可保留多个高质量轨迹，避免只模仿一种调度风格
最好合法 makespan奖励归一化、模型选择和结果对比它是当前已知最好值；没有证明时不能当作真实最优值
下界与 gap判断参考标签质量，区分“已证明好”和“当前最好”只使用完整问题有效下界，不混用周期子问题下界
求解状态与耗时构造 curriculum，识别对不同算法困难的实例难度由实测结果定义，而不是只按 wafer 数预设

建议的训练顺序：先用多算法产生的高质量合法轨迹做行为克隆，使策略掌握基本动作选择；再用 PPO 在环境中优化长期 makespan；最后在未见 Recipe、未见拓扑和更大 workload 上评估泛化。

7. 下一步最重要的实验

下一阶段的重点不是继续增加 Pipeline 功能，而是用统一实验回答两个问题：四类算法在什么问题上各自有效？这些标签是否真的能提升学习策略？

实验 A：求解器横向比较

  • 按拓扑、Recipe 数和 wafer 规模分层抽取 pilot；
  • 对四类方法设置可比较的时间预算；
  • 报告有效解率、makespan gap、首次可行时间和最终耗时；
  • 单独分析周期适用场景与一般非周期场景；
  • 给出每类问题的 winner 分布，而不是只报全局平均值。

实验 B：标签对训练的贡献

  • 从零开始 PPO vs 行为克隆预训练 + PPO；
  • 只用单一 solver 轨迹 vs 使用多 solver 高质量轨迹；
  • 只用最好轨迹 vs 保留 top-k 多样化轨迹；
  • 随机采样训练 vs 按实测难度做 curriculum；
  • 比较 success、normalized makespan、deadlock 和 OOD 泛化。

最终希望得到的不是“某算法永远最好”，而是一张问题特征到算法表现的经验地图，以及一套被证明能改善 RL 训练的标签选择策略。

8. 当前边界与汇报结论

当前已经具备

  • 有限真实拓扑族上的受控问题生成；
  • Recipe、时间和 workload 的多样化采样；
  • 四类调度算法与统一物理合法性验证；
  • 将动作轨迹和参考 makespan 接入学习系统的基础条件。

当前最需要补齐

  • 四类算法在统一 pilot 上的系统效果对比；
  • 标签质量、多样性与 RL 收敛之间的实证关系；
  • 根据真实机台数据调整拓扑和任务采样权重；
  • 后续再扩展清洗、LOAD_LOCK、residency 等复杂约束。

结论：当前工作的核心价值，是把“接近真实分布的问题生成”“互补算法提供标签”和“学习型调度训练”连接成一个可以验证的研究闭环。下一步的重点应从工程完善转向算法 benchmark 与训练收益验证。
